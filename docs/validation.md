## 20명 부하 측정

실제 REST로20개 게스트를 만들고 WebSocket을 연결해 이동·강화·리스폰 입력을 보냈습니다. Uvicorn 단일 프로세스, SQLite 통계 저장,15초 측정입니다.

- 동시 접속 최고: 20명
- 수신 snapshot: 3,019개
- 클라이언트 전체 수신: 11,647,042바이트
- 클라이언트당 수신: 약 38,823바이트/초
- 서버 틱 처리시간 표본 중앙값: 0.511ms
- 서버 틱 처리시간 표본95백분위: 1.537ms
- 틱 deadline 초과: 0회
- 연결 오류: 0개
- 통계 저장 오류/큐 초과: 0 / 0

원시 결과는 load-result.json에 있습니다. tick_ms는0.2초마다 health에서 읽은 최근 틱의 표본입니다. 모든 틱의 정확한95백분위는 아닙니다. 특정 하드웨어에서의 짧은 스모크 테스트이며 장시간 안정성·다른 서버·MySQL 운영 성능을 보장하지 않습니다. 렌더링60FPS를 측정해 보장한 것도 아닙니다.

부하 과정에서 강화 중복 요청 및 리스폰 남은 시간 반올림으로 조기 요청이 거부되는 문제를 수정했습니다. 현재 강화 선택 번호로 중복 요청을 억제하고 리스폰 시간은 올림하여 표시합니다.

## 첫 수동 테스트 시나리오

1. `.env` 생성 후 `docker compose up --build -d`, 모든 서비스 상태를 확인합니다.
2. 일반 창과 시크릿 창에서 http://localhost:8080 에 접속합니다.
3. 서로 다른 닉네임으로 들어갑니다. HUD 접속2명, 각 화면에 두 도트 캐릭터를 확인합니다.
4. A에서 D를 눌러 이동합니다. B 화면에서도 A가 이동해야 합니다. W+D 대각선 이동이 한 방향보다 빨라지면 실패입니다.
5. 장애물과 월드 끝을 향해 이동합니다. 통과하거나 경계 밖으로 나가면 실패입니다.
6. 중앙 안전구역 밖으로 이동합니다. 몬스터와 투사체가 보이고, 처치 시 EXP가 올라가야 합니다.
7. 레벨업 시3개 선택지를 확인합니다. 선택하면 스탯/무기가 바뀌고 중복 클릭으로 연결이 끊기면 실패입니다.
8. 두 유저가 안전구역 밖에서 근접합니다. 자동 공격·HP 감소·사망·킬 피드·3초 대기 후 리스폰을 확인합니다.
9. 리스폰한 유저의 전투 레벨은1, HP는 초기값, 누적 세션 킬/데스는 유지되어야 합니다.
10. 한 창의 네트워크를 끊고 복구하여 재접속 버튼을 누릅니다.5초 안이면 기존 전투 상태를 복구하고 이후에는 같은 게스트의 새로운 생존 상태로 입장합니다.
11. B에서 나가기를 누릅니다. A의 접속 수는 즉시1명, B의 캐릭터는 유예5초 후 사라져야 합니다.
12. backend를 재시작합니다. 월드/전투 상태는 초기화되고 `GET /api/leaderboard`의 DB 누적 기록은 유지되어야 합니다. 이 마지막 항목은 실제 MySQL에서 추가로 확인해야 합니다.

## 제한과 미검증 항목

자동 재접속·토큰 분실 복구·지연/패킷 손실 시 보정 품질·장시간 몬스터 배치·다중 계정 악용 방어·내구성 통계 큐·DB 장애 복구는 아직 충분히 구현/검증하지 않았습니다. 공격/성장/리스폰은 서버 로직 테스트를 수행했으나 전체 전투의 모든 UI 경로를 E2E 자동화하지는 않았습니다.

Phaser가 포함된 JS 번들은 gzip 약370KB이고 빌드가 큰 chunk 경고를 출력합니다. 이는 빌드 실패가 아니며 초기 로딩을 개선하려면 게임 진입 시 동적 import를 추가할 수 있습니다.

## Phase V1 추가 검증

V1 환경 테스트와 PNG 실패 대체 테스트를 포함한 Chromium E2E3개가 통과했습니다. 백엔드14개 테스트와 빌드가 통과했으며, 서버/예측/프로토콜은 변경하지 않았습니다. 실제 전후 RAF 표본과 성능 감소는 phase-v1.md와 v1-performance.json을 확인하세요. Docker/MySQL 기동은 여전히 미실행입니다.

## Phase V2 검증 (이전 단계 기록)

- 프로덕션 빌드 및 백엔드14개 테스트 통과.
- Chromium E2E6개 통과(36.7초): V1 맵 회귀, PNG 실패, 두 브라우저 이동/방향/Idle·재접속, 캐릭터 표시 상태 재생, 몬스터 표시/정리/AOI, 실제 전투 사망/리스폰.
- V1 ZIP과 보호 파일68개(백엔드42개 포함) 바이트 동일. v2-preservation.json 참고.
- 실제 sprite PNG/명세 검사와 화면 확인 완료. v2-asset-validation.json 참고.
- 성능 표본은v2-performance.json, 설명은phase-v2.md. GPU/저사양/장시간 렌더링 성능 보장은 아님.
- Docker/MySQL·외부 HTTPS/WSS는 계속 미실행. V2 당시 V3/V4는 미구현이었습니다. 현재 V3 결과는 아래 기록을 확인하세요.

## Phase V3 검증 (이전 단계 기록)

백엔드23개 테스트, vue-tsc/프로덕션 빌드, Chromium E2E10개(56.3초)가 통과했습니다. 실제 PvP·이동/재접속·PNG 실패 대체·V1맵/V2캐릭터 회귀·사망/리스폰·이벤트 재생/중복 방지·효과 포화/게임 종료 정리를 포함합니다. 240투사체/3만 고유 이벤트/300회 재사용 검사는 표시 전용 패킷과 가상 시간입니다.

V2와3600틱 권위 상태 비교 차이0, 보호 파일45개 바이트 동일, 실제 PNG/16시트 프레임 검사 완료. 실제 20연결(Chromium 화면1+WS봇19)/120초 검사에서 페이지/봇 오류0, 마지막 누적 RAF30.18FPS, 효과 이미지 최대54/192·문자5/40, 퇴장/종료 정리 성공. 서버 tick 마지막 표본0.483ms·누적 overrun5회·통계 실패/큐 거부0입니다.

60FPS 목표는 이 환경에서 미달입니다. 실제 GPU 성능·Docker/MySQL·외부 WSS·30분 안정성은 미검증입니다. 원시 결과와 재현 방법·상세 완료 판정은phase-v3.md, v3-soak.json/JSONL, v3-performance.json에 있습니다. V4는 미구현입니다.

## Phase V4 검증 (현재 통합 버전)

백엔드23개 테스트, 타입/프로덕션 빌드, Chromium13개 테스트가 통과했습니다. 실제 성장/강화 선택과PvP는 임시 실제 서버(seed83)에서, 실제 사망/리스폰과멀티플레이/재접속·V1맵/V2캐릭터/V3효과 회귀는 기존 테스트 서버에서 검사했습니다. 표시 재생은 별도 UI 배치 검사로 구분합니다.

3개 PC 해상도와UI100%/125%,1093×614 확대 등가 viewport를 확인했습니다. 서버44개를 포함한보호 파일112개 바이트 동일입니다. 실제3해상도 RAF 표본은v4-performance.json, 완료 기준/한계/실제화면 구분은phase-v4.md입니다. Docker/MySQL·외부WSS·30분 검사는 계속 미실행이고GPU60FPS 보장도 없습니다. V3의20연결120초 검사를V4에서 다시 실행한 것은 아닙니다.

현재 실제1플레이어·안전구역·Chromium134 headless의4초 RAF 표본은1366×768:52.10FPS,1920×1080:26.70FPS,2560×1440:17.17FPS입니다. 페이지 오류0,60FPS 미달이며 실제GPU/지속 전투 보장은 아닙니다. 최종빌드6.04초, JSgzip387KB와큰chunk 경고가남았습니다.
