# Phase V2 — 캐릭터·일반 몬스터 시각 시스템

V2 구현 및 검증 결과입니다. Phase V3/V4는 진행하지 않았습니다. 서버에 종류 필드가 없는 일반 몬스터만 구울 외형으로 교체했고, 빠른/강력한 종류는 미구현입니다.

## 변경과 보존

V1의2프레임 도형 플레이어와 정적 도형 몬스터를 투명 PNG 시트로 교체했습니다. 플레이어는 방어구·청록색 망토·석궁, 일반 몬스터는 뼈·회청색 피부·갈색 천·황색 눈으로 구분됩니다. 원격 플레이어는 약한 보라색 틴트를 적용합니다. 닉네임·Lv.·HP와 접지 그림자가 본체 위치를 따르며, 기존 카메라 줌이 모든 월드 표시를 함께 확대합니다.

기존4096² 월드, 입력50ms 주기, 서버20tick/초,10snapshot/초, 충돌/AI/자동 공격/성장/리스폰/프로토콜을 보존했습니다. 백엔드42개 파일, V1 환경 코드·기존 에셋, input/prediction/network를 포함한68개 보호 파일을 V1 ZIP과 바이트 비교했습니다. 차이0개입니다. 결과는 `v2-preservation.json`에 있습니다. TS 프로토콜에서는 기존 몬스터 인라인 타입만 이름 있는 인터페이스로 추출했습니다.

## 렌더링과 상태 흐름

스냅샷 HP 감소→200ms Hit와 짧은 붉은 틴트. 플레이어 alive=false→방향별 Death,500ms 마지막 포즈를 시간으로 확정,700ms까지 페이드. false→true→같은 렌더러를 초기화하고 출현 알파/그림자 변화. 신규 접속도 동일 출현 표현입니다. 위치는 로컬 예측 또는 원격 서버 좌표를 기존 지수 보간으로 따라갑니다. 실제 화면 좌표 변화로 Walk를 판정하며 정지 시Idle로 전환합니다. 큰 순간 보정/리스폰 이동은 걷기로 해석하지 않습니다.

몬스터는hp 감소로Hit를 판정하지만 사망 이벤트가 프로토콜에 없습니다. 새 스냅샷에서 사라진 직전 몬스터가 플레이어 중심±850×550 내부에 있었으면 사망을 **시각적으로 추정**해700ms 유지합니다. 서버 관심 영역±950×650의 경계 근처/밖에서 사라지면 즉시 정리합니다. 이는 권위 있는 사망 데이터가 아니므로 경계의 실제 처치는 애니메이션 없이 사라질 수 있습니다. 서버 재시작/아주 긴 스냅샷 지연 같은 조건도 완전히 구분하지 못합니다. 게임 보상/충돌/AI는 이 추정을 사용하지 않습니다.

발 depth=10000+y+16을 유지했습니다. 그림자는V1 shadow depth, HP/이름은40000대이며 Foreground의 가림 처리와 좌표는 그대로입니다. 화면 밖 Sprite/오버레이를 숨기고 프레임마다 생성하지 않습니다. 렌더러는 엔티티당 타이머나 애니메이션 이벤트를 등록하지 않으며 destroy가 Sprite·shadow·bar·barBack·label을 정리합니다. 완료된 일회 애니메이션을 매 프레임 재시작하지 않습니다.

## 실행과 두 브라우저 검사

```bash
cp .env.example .env
docker compose up --build -d
```

http://localhost:8080 일반 창과 시크릿 창에서 서로 다른 이름으로 접속합니다. WASD/방향키 이동 때 이동 방향과 걷기가 일치하고 손을 떼면Idle이어야 합니다. B 화면에서도 A의 방향/움직임/정지가 보이고 이름·HP·레벨이 따라와야 합니다. 나무/기둥 앞뒤 이동 시 V1 가림이 유지되어야 합니다.

중앙 안전구역 밖에서 실제 몬스터/상대와 싸워 붉은 피격·HP 감소·사망 포즈와 페이드를 확인합니다. 사망 후3초 대기, '다시 생존하기'를 누르면 중앙에 나타나며 HP와 레벨을 서버가 초기화해야 합니다. 네트워크 종료/재접속과 상대 나가기도 확인합니다. 초기 위치에는±40 랜덤 오프셋과3초 보호가 있어 전투 시나리오가 즉시 발동하지 않을 수 있습니다.

```bash
# 실행 중인 개발 서버 대상, Uvicorn8000 + Vite8080 필요
cd frontend
npm ci
npm run build
npx playwright install chromium
npx playwright test
# 서버 회귀는 backend에서
python -m pytest -q
```

운영주소 ARENA_URL을 지정하면 내부 렌더러 검사 테스트는 건너뛰며, 개발에서만 __ARENA_GAME__ 참조가 존재합니다. 모든 브라우저 검사는 실제 Uvicorn/Vite에서 수행하고 DB는SQLite를 사용했습니다. Docker/MySQL 기동은 이 환경에Docker가 없어 **미실행**입니다. 외부 WSS·장시간 부하·모바일과 저사양 기기의 프레임률은 미검증입니다.

## 시각적 한계와 다음 단계 경계

원본 생성 포즈의 장비 위치·발 간격에 미세한 흔들림이 있고 일부 프레임은 재사용합니다. Hit는 별도 공격이 아니라 피격 시각 표현입니다. 출현은 간단한 페이드이며 별도 마법 이펙트 시트는 없습니다. 서버에 공격 애니메이션/몬스터 종류 상태가 없어 새 공격 모션·빠른/강력한 종류를 추가하지 않았습니다. 정교한 투사체·폭발·EXP 효과·대규모 HUD/메뉴 개선은V3/V4 범위로 남겨 두었습니다.

최종 Chromium E2E는6개 모두 통과(36.7초), 페이지 오류0개입니다. 서버 테스트에는 의존성 deprecation warning1개가 있습니다. 네트워크/이동 검사는 실제 서버 연결,4방향·짧은 피격 상태의 세부 검사는 서버 전투와 분리한 클라이언트 표시 재생입니다. 실제 전투 검사는 서버 상태를 조작하지 않고 안전구역 밖 이동→자동 공격/몬스터→사망→3초 대기→리스폰 버튼을 사용했습니다.

검증 중 공유 월드의 전투 잔재,5초 접속 유예 캐릭터의 검사 대상 오선택, 테스트의 Phaser 전체 객체 반환으로 생긴 지연을 수정했습니다. 동기화 검사는 서버ID로 대상을 식별하고 안전구역 중심을 향해50px 이상 이동합니다. 짧은Hit 상태는 같은 화면시간에 직접 렌더링하여 확인합니다. 낮은FPS에서도Death는500ms에 마지막 포즈를 확정합니다.

**V2 요청 범위 구현과 이 환경의 회귀/브라우저 검증 완료. V3/V4 미구현.** 전체 운영 환경 검증 완료를 의미하지 않습니다.

## 렌더링 성능 표본

별도 V1 사본과 V2를 동일1280×800 Chromium134 headless/WebGL에서 순서대로 실행했습니다. 각2.2초 예열 후4초 RAF, 컨텍스트 종료 뒤5.5초 유예입니다. 테스트·빌드와 동시에 측정하지 않았습니다.

| 표본 | RAF FPS | 프레임95백분위 | 환경 표시 |
|---|---|---|---|
| V1 기준 | 35.25 | 33.4ms | 2타일층,361prop 중56표시,16dust |
| V2 | 37.16 | 33.4ms | 동일 환경 수 |

이 짧은 표본에서 V2로 인한 큰 추가 하락은 관찰하지 않았습니다. 약5.4%의 수치 차이를 개선 효과로 단정하지 않습니다. 몬스터/플레이어 배치와 난수·CPU부하가 동일한 통제 실험은 아닙니다.60FPS·20명/80몬스터 장시간 렌더링을 보장하지 않습니다. 두표본페이지 오류0개. 원시결과는v2-performance.json이며 frontend/scripts/benchmark-v2.mjs로재측정할 수 있습니다.

실제 화면은preview-after-v2.png,respawn-v2.png,전후 표본은benchmark-v1-baseline.png/benchmark-v2.png입니다. 플레이어가 가까우면 이름/HP가 겹칠 수 있으며 오버레이 충돌 회피는이번단계에서구현하지 않았습니다.
