# 완료 판정과 다음 작업

## 개발 순서

Phase0 설계 → Phase1 환경 → Phase2 이동 → Phase3 두 연결 → Phase4 몬스터/총알 → Phase5 성장/무기 → Phase6 PvP → Phase7 측정/수정 → Phase8 배포 설정 순서로 진행했습니다. 초기4개 서버 테스트와 빌드가 통과한 뒤 전투 코드를 추가했습니다. 이후 전투 테스트, 두 브라우저 테스트,20명 부하 테스트에서 발견한 문제를 수정했습니다.

## 남은 완료 조건

- Phase1 운영 스택 검증: 실제 Docker에서 MySQL8.4 migration, 게스트 생성, 누적 통계, 재기동 볼륨 유지까지 확인
- Phase7 운영 안정성:30분 이상 부하·장시간 미접속 지역 몬스터 누적·반복 입퇴장·DB 장애·네트워크 지연/손실·백프레셔를 검증
- Phase8 외부 배포: 배포 서버와 도메인 확보, 인증서/터널 설정, 다른 네트워크의 두 사용자 접속, HTTPS/WSS와 DB 백업 확인

위 항목은 코드가 있다는 이유로 완료 처리하지 않았습니다.

## 다음 확장 우선순위

1. 실제 MySQL/Compose smoke test와 외부 접속 검증
2. 메모리 통계 큐 대신 트랜잭션 outbox/이벤트 ID를 적용해 중복·유실 방지
3. 토큰 유지/복구 정책, 게스트 정리/보존 기간, 신뢰 프록시 IP 기반 생성 제한
4. 이동 예측 지연·보정 시각 효과, 다른 플레이어 시간 기반 버퍼 보간, RTT 측정
5. 미접속 지역 몬스터 정리·지역별 밀도, 장애물 우회 경로, 빠른/원거리/정예 몬스터
6. PvP 성장 밸런스, 게스트 재생성에 대한 반복 처치 악용 억제, 리스폰 보호의 시각적 명확성
7. 음향·설정·모바일 입력·게임 안내, 무기 업그레이드 상세 수치
8. 측정에 따른 Delta snapshot, 객체 풀, 월드 분할·라우팅

현재 게임 서버의 실시간 상태는 객체 기반입니다. 신규 전투 시스템이 늘면 World의 simulate에서 각 system을 호출하는 구조로 더 분리할 수 있습니다. 지금은 main.py/App.vue와 실제 규칙을 분리하면서 불필요한 추상화 계층을 만들지 않았습니다.
