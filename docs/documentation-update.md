# 한글 주석·폴더 설명 정리

게임이 정상 동작함을 사용자가 확인한 V1~V4 재검증 버전을 기준으로 문서와 주석을 정리했습니다. 게임 규칙·UI 동작·에셋·의존성 버전을 바꾸지 않았습니다.

## 적용 범위

- 루트 README: 실제 전체 폴더 구조, 핵심 진입 파일, 유지보수 대상별 수정 위치, REST/WS/DB/화면 데이터 흐름.
- 관리 대상 41개 폴더: README에 역할, 직접 포함된 파일, 하위 폴더, 프로젝트 루트 링크, 변경 시 점검 항목. 기존 실행/에셋 출처 설명은 보존.
- Python 36개와 프론트엔드 51개 소스: 파일 책임과 함수/메서드별 한글 주석. 테스트·부하·에셋 제작 코드도 포함.
- 배포/개발/CI·마이그레이션 템플릿·환경/의존성/제외 설정에도 한글 역할 설명.
- JSON/lock은 주석을 넣지 않고 README의 파일 표에서 주요 필드를 설명. PNG와 제3자 라이브러리/생성 dist/캐시는 편집하지 않음.

주석은 실행 순서를 읽기 위한 안내입니다. 서버가 HP·명중·보상을 결정하고 클라이언트는 예측 이동과 표현만 수행하는 경계를 유지하세요. 규칙을 수정하면 관련 주석도 갱신해야 합니다.

## 변경이 실행에 영향을 주지 않는지 확인

- Python 36개: 주석/위치 정보를 제외한 전체 AST가 기준 버전과 동일.
- TS/Vue/MJS/CSS 51개: 실행 구문 구조와 리터럴이 동일. Vue 템플릿/스타일 내용은 동일, CSS 선언은 주석 제외 동일.
- 운영 빌드의 JS/CSS 파일: 이전 재검증 버전의 빌드와 파일 내용까지 동일 (`index-ZursrRsV.js`, `index-D81c9IH1.css`).
- 설정 17개: 주석을 제외한 내용 동일. Alembic 템플릿에도 안내 주석만 추가.
- 모든 기존 PNG/JSON/JSONL: 바이트 동일. 과거 검증 JSON은 그 당시의 기록으로 유지.
- README 링크와 41개 폴더 README 누락: 검사함.

## 이번 실행 검증

프론트 빌드 통과, 서버 23개 테스트 통과(0.67초), Chromium 13개 테스트 통과(약 1.4분). 빌드의 기존 번들 크기 경고와 서버 의존성 deprecation 경고 1개는 유지되었습니다. V1 맵, V2 시각 상태, V3 이벤트/PvP/풀, V4 설정/해상도/성장/사망, 2인 이동·재접속 검사를 포함합니다. 상세 결과는 옆의 `documentation-validation.json`에 기록합니다. Docker/MySQL/외부 HTTPS·실제 GitHub Actions·장시간 성능은 이번 문서 작업에서 실행하지 않습니다. CI 파일은 Compose와 브라우저 실행까지 정의되어 있으나 이번 로컬 검사 성공을 CI 성공으로 표시하지 않습니다.

이전 `v4-preservation.json`과 ZIP 재검증 기록은 각 작업 시점의 바이트/테스트 기록입니다. 이번에는 주석을 추가했으므로 소스 파일의 이전 SHA는 달라집니다. 동작 유지 여부는 이번 AST/구문/운영 JS·CSS 비교와 기존 테스트 결과로 판단합니다.

## 읽기 순서

1. 루트 README에서 전체 폴더와 수정 시작 지점을 찾습니다.
2. 해당 폴더 README의 파일 역할과 하위 폴더 설명을 읽습니다.
3. 소스의 역할 주석과 함수 위 주석을 읽어 입력/출력·상태 권한·정리 순서를 확인합니다.
4. 서버 규칙 변경은 backend 테스트, UI/렌더링 변경은 frontend 빌드 및 해당 브라우저 테스트로 확인합니다.

새 폴더는 README를 함께 만들고, 새 API/이벤트/필드가 추가되면 서버/프론트 계약과 관련 문서를 동시에 갱신합니다. 기존 API/WS와 Compose 실행 방법은 루트 README를 따릅니다.
